Show a custom Discord Rich Presence (the “Playing…” status under your name) for any app or game on your PC — automatically, with no need to keep a script running by hand.

This guide covers everything from a first-time setup to the advanced KanColle live-data mode. If you just want the basics working in five minutes, follow Quick Start below and stop there — everything after it is optional.

What this does

  • Watches the programs running on your PC.
  • When one you’ve set up starts, it shows a custom status on your Discord profile — your own text, your own images, optional clickable buttons, and an optional party/team size counter.
  • When it closes, the status clears automatically.
  • Can launch with Windows and run quietly in the background, so once it’s set up you never have to touch it again.
  • Keep as many separate config files as you like, and switch between them from the File menu.
  • Optional: for the browser game KanColle (via the Damecon browser), it can show live info — your Admiral level, current fleet, sortie status, and resources — updating in real time instead of a fixed message.

Comes ready to go: the starter config.json

This app ships with a config.json already partly filled in, so most people can skip building anything from scratch. Out of the box it includes:

Group What it’s set up for
KanColle — Static text A fixed, unchanging status for KanColle (via Damecon), showing a server/anchorage line and an ID line. Disabled by default.
Girls’ Frontline 2: Exilium A fixed status for GF2, showing a UID and server line. Enabled by default.
KanColle — Dynamic The full live-data version for KanColle, with Watch live game data already turned on. Holds six ready-made Variant presets (see below) — one is enabled by default, the other five are there to try or repurpose.

The KanColle Dynamic group’s six presets, all using the placeholders explained in Advanced: KanColle Live Data:

Preset Shows
Kancolle Preset 1 Fleet status + map location + fleet composition as Details; a dynamic party count (total ships held, shown as Discord's party number out of 100) instead of a plain ship-count line. Disabled by default — a good one to enable if you want the party counter.
Kancolle Preset 2 Fleet status + fleet composition as Details; ship count and resources as State. Enabled by default — the most “at a glance” of the six.
Kancolle Preset 3 Adds the current map node and battle rank on top of Preset 2’s info. Disabled by default — the most detailed option.
Kancolle Preset 4 Same information as Preset 2, reordered — fleet name and ship count lead, status comes last, and resources are separated with slashes instead of pipes. Disabled by default.
Kancolle Preset 5 Same information as Preset 2, styled with brackets around the fleet name and each resource spelled out with its own label (Fuel/Ammo/Steel/Bauxite). Disabled by default.
Kancolle Preset 6 The most compact styling of the six — dot separators throughout and single-letter resource labels (F/A/S/B). Disabled by default.

Heads up: Preset 1’s State text currently ends with a literal “Ships held” with no number in front of it (it reads ...| Ships held instead of ...| {ship_count} Ships held) — worth double-checking if you plan to enable that one, in case a placeholder got dropped by accident while editing.

To use any of these, just:

  1. Select the Group/Variant you want in the app.
  2. Replace the placeholder Client ID with your own (see Quick Start, step 2, for how to get one).
  3. Optionally edit the personal details already sitting in the text — e.g. the example admiral/UID numbers in Details/State — to your own, or leave them out entirely.
  4. Enable the Group if it isn’t already, and disable whichever ones you’re not using.

Nothing here is locked in — you can freely edit, delete, or add new Groups/Variants the same way described in Quick Start below, whether that’s tweaking these examples or setting up an entirely different game.

Requirements

  • Windows (some features — starting with Windows, and the KanColle live-data mode — are Windows-only; the core Rich Presence feature works anywhere Python/the app runs, but this guide assumes Windows since that’s what the .exe is built for).
  • Discord desktop app, installed and running. (Rich Presence does not work through Discord in a browser tab.)
  • A free Discord account — you’ll create one small “Discord Application” per look you want to show (takes under a minute each; explained below).

Quick Start (5 minutes)

  1. Download and run DiscordRPCManager.exe. config.json will be created automatically next to it the first time you run it — that file stores all your settings, so keep it in the same folder as the .exe.
  2. Create a Discord Application:
    • Go to the Discord Developer Portal → New Application.
    • Name it whatever you want shown as the title on your Discord profile (e.g. “Minecraft”, “My Cool Status”) — this name becomes the bold title line, so pick it carefully.
    • Copy the Application ID shown under General Information — this is your Client ID.
  3. In the app, click Add Group:
    • Process Name: the exact .exe name of the program you want to track, as it appears in Task Manager → Details tab (e.g. notepad.exe, javaw.exe).
    • Leave it Enabled and click Save.
  4. Select the new Group, click Add Variant:
    • Discord Client ID: paste the Application ID from step 2.
    • Details / State: the two lines of text you want shown.
    • (Optional) Large Image Key / Large Image Text: either an asset key you uploaded under your Discord Application’s Rich Presence → Art Assets tab, or a direct image URL (e.g. https://i.ibb.co/yourimage.png) — both work, see Images below.
    • Click Save.
  5. Click Start Monitoring.

That’s it — open the program you configured, and your Discord status should update within a few seconds (check the Activity Log at the bottom of the window if it doesn’t).

Understanding Groups and Variants

  • A Group = one program (one process name) you want to track.
  • Each Group holds one or more Variants — a full look (Client ID + text + images). If a Group has more than one Variant, one is picked at random every time that program starts, and it stays active the whole time that program keeps running. Next time it launches, a new one is rolled.

This is useful if you want some variety — e.g. two or three different flavor messages for the same game, shown randomly each session — without having to pick one manually every time.

Important: the bold title line on Discord is not free-form for every setup — normally it comes from the name you gave the Discord Application in step 2. This app also supports a Discord Name field per Variant, which can override that title independently of the Application’s registered name — if you want different Variants under the same Group to show different titles, set a different Discord Name on each, using the same Client ID.

Images: asset key or direct URL — both work

For Large Image Key and Small Image Key, you have two options:

  • An asset key — upload an image under your Discord Application’s Rich Presence → Art Assets tab, and enter the name you gave it there.

  • A direct image URL — paste a full link straight to an image file, e.g.:

    https://i.ibb.co/7tXZBHyx/Kantai-Collection-logo.png

    No uploading to Discord needed — free image hosts like ibb.co work well for this. Just make sure the link points directly at the image file itself (not a webpage that merely displays it), and that it stays online — if the host ever takes the image down, the image will stop showing on Discord.

Both approaches work equally well; pick whichever is more convenient. The starter config that ships with this app uses direct URLs for its example images. (Note: what Discord calls the image “Text” field — the tooltip shown on hover — appears in this app as Large Image Text / Small Image Text.)

Each image also has an optional Large/Small Image URL field — set this and clicking the image on Discord opens that link in a browser, e.g. linking your large image to your community’s Discord server or website.

Party — show a “X of Y” count

Under the Party section of a Variant, two fields:

  • Party Current — e.g. 2
  • Party Max — e.g. 5

Set both to show something like (2 of 5) next to your State line on Discord — useful for anything with a group/team/lobby size. Leave Party Max at 0 (the default) to hide this entirely.

Dynamic Party Current: tick Dynamic Party Current (use {ship_count}) below the Party fields and, instead of a fixed number, Party Current will automatically track your live {ship_count} (total ships held) — handy for a KanColle Variant with live data enabled, so the count updates on its own as your roster grows, with Party Max acting as the cap (e.g. 100, your storage limit).

Buttons — up to two clickable links

Under the Buttons section of a Variant, you can set up to two buttons that appear on the activity card:

  • Button 1/2 Label — the button’s text, e.g. Visit Website (max 32 characters)
  • Button 1/2 URL — where it goes, must start with http:// or https://

Both the label and URL must be filled in together for a button to show — leave both blank to skip it.

Important Discord quirk: buttons are only visible to other people looking at your profile — Discord never shows your own activity’s buttons back to you. If you’ve set one up correctly and it’s not appearing, ask a friend to check your profile rather than assuming it’s broken.

Startup Options

Found in the box near the top of the window. All three are optional, and combine well if you want the whole thing to run with zero clicks after the first setup:

Option What it does
Auto-start monitoring on launch Skips clicking “Start Monitoring” — it begins the moment the app opens.
Minimize to tray immediately after launch Hides straight to the system tray instead of showing the window. Right-click the tray icon any time to reopen it, or to stop/start monitoring.
Start with Windows Registers the app to launch automatically every time you log into Windows.

With all three on: log in → the app launches → starts monitoring → hides itself. You’ll never need to open it again unless you want to change something.

Managing multiple config files

You’re not limited to a single config.json. Use the File menu at the top of the window:

Menu item What it does
New Config Clears everything currently loaded and starts a blank setup. Asks first if you have unsaved changes.
Open Config… Loads a different .json file you’ve saved before, replacing what’s currently loaded.
Save Saves to whichever file is currently loaded (shown in the window’s title bar).
Save As… Saves the current setup to a new file, and switches to using that file from now on.

This is useful for keeping separate setups for separate purposes — e.g. one config for gaming nights, another for work-from-home apps — and switching between them without having to rebuild anything. Switching files stops monitoring first if it’s running, and the window title always shows which file is currently active.

Advanced: KanColle Live Data (optional)

This section is only relevant if you play KanColle (Kantai Collection) through the Damecon browser and want your Discord status to show live info — Admiral level, current fleet, sortie/battle status, resources — instead of fixed text.

How it works

Damecon is built on Electron (Chromium), and KanColle’s client fetches all of its game data as plain JSON over the network. This app reads that same traffic locally, the same way established community tools for this game already do — it does not read game memory or inject code into the game itself.

Setup

  1. Launch Damecon with two extra flags. The easiest way is to edit its shortcut:

    • Right-click your Damecon shortcut → Properties → Shortcut tab → Target field.

    • Add to the end of the existing path:

      --remote-debugging-port=9222 --remote-allow-origins=*

    • The full Target line should look like:

      "C:\Path\To\damecon-browser.exe" --remote-debugging-port=9222 --remote-allow-origins=*

    • Both flags are required — the first opens the debug connection, the second is required by Chromium for the connection to actually be allowed.

    • Always launch Damecon from this shortcut going forward.

  2. In the RPC Manager, add a Group with Process Name damecon-browser.exe.
  3. Inside that Group’s settings, find Live data (KanColle-style, via Chrome DevTools) and enable Watch live game data. Leave the CDP port at 9222 unless you changed it above.
  4. Add a Variant as usual, but use placeholders in Details/State instead of fixed text. The full set:

Admiral

Placeholder Shows Example
{admiral_nickname} Admiral/player nickname Haru
{admiral_level} Admiral/HQ level 86
{admiral_rank} Admiral rank value 1

Fleet & Ships

{fleet_name} Fleet #1’s name (」゜ロ゜)」
{fleet_status} Current high-level status — in port, on expedition, on sortie, in battle, or a battle result On Sortie: World 1-5
{fleet_ship_count} Ships currently assigned to Fleet #1 4
{ship_count} Total ships held 120

{map_area} World/area number 1
{map_info} Map number within that world 5

Example:

State:   {ship_count} Ships held | Resource: {fuel} | {ammo} | {steel} | {bauxite}

A couple of things worth knowing:

  • {map_node} isn’t guaranteed for every map — it’s resolved from a community-maintained dataset covering the regular World 1–7 maps. Event maps aren’t necessarily covered, so don’t rely on it there until you’ve confirmed it works for that specific event.
  • {map_area}-{map_info} describes the world/map (e.g. “World 1-5”), while {map_node} describes the node you’re currently on within it (e.g. “J”) — they answer different questions and are often used together.
  1. Open KanColle in Damecon and start monitoring. Give it a little while after opening — some of this data (like your Admiral level) is only sent by the game once, right when it loads, so a few fields may show a dash or stay blank at first. If you use a placeholder name that doesn’t exist (a typo, for instance), it’ll show as a literal ? instead — that’s your signal something’s misspelled, not that the data isn’t ready yet.

If real data never shows up, check the Activity Log — it reports exactly what it did and didn’t manage to read.

Troubleshooting

Nothing shows up on Discord at all:

  • Is the Discord desktop app actually open?
  • Is the Group enabled, and does its Process Name exactly match what’s in Task Manager?
  • Does the active Variant have a real Client ID (not left blank, not still saying “YOUR_DISCORD…”)?
  • Check the Activity Log for a connection error.

Two Variants look identical on Discord even though I set different text:

  • If they share the same Client ID and you didn’t set a Discord Name on each, the title will be identical — only Details/State will differ. Set a distinct Discord Name per Variant, or use separate Discord Applications, if you want fully distinct-looking activities.

Can I use the same Client ID for multiple games/Groups at once?

  • A single Discord Application (Client ID) can only power one active connection at a time — that's a Discord limit, not something this app controls. It's fine to reuse the same Client ID across different Variants as long as they're never meant to show at the same moment (which is normally the case here anyway, since this app only ever displays one activity at a time).
  • Where this actually causes a problem: running two separate things that both try to connect with the same Client ID simultaneously — for example, two copies of this app pointed at different configs, or this app running alongside another Rich Presence tool sharing the same Client ID. Only one connection can hold that Client ID at a time; the other will fail to connect or get bumped.
  • The fix is simple: give each game/project its own Discord Application (a new one takes under a minute to create — see Quick Start, step 2) rather than sharing one Client ID across anything that might run at the same time.

KanColle placeholders showing a dash, blank, or not updating:

  • Confirm Damecon was launched with both flags (--remote-debugging-port=9222 and --remote-allow-origins=*) — missing either one breaks the connection.
  • Confirm the Activity Log shows “KanColle live-data watcher attached.”
  • Some fields (Admiral info) only refresh once per game load — try reloading the KanColle page or try click at the repair dock then go back to port (Home screen) once with the manager running.
  • If a placeholder shows a literal ? instead, double-check its spelling — that specific symbol means the name isn’t recognized at all, not that the data just hasn’t arrived yet.

I moved the .exe and now “Start with Windows” doesn’t work:

  • Untick and re-tick that checkbox once so it re-registers the new file location.

A note on how this works, for the curious

This app talks to Discord using the same official local Rich Presence connection any game uses — nothing here reads private data, modifies Discord itself, or requires special permissions beyond running as a normal Windows program. The optional KanColle mode reads network traffic the game already sends to your own browser; it doesn’t alter the game or interact with the game server on your behalf.
